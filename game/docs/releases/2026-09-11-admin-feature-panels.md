# 后台功能分区与移动端整理

本次改动针对后台表单堆叠、操作与列表混杂、手机和平板需要反复滚动才能定位功能的问题。

## 变化

- 后台业务区域统一使用带标题、边界和间距的功能卡片；管理员按钮改为清楚的实体按钮。
- 道具目录优先显示搜索、筛选和列表；顶部提供新建与生成工具入口。材料生成、灵种生成、每日自动生成及完整编辑器按需打开抽屉。
- 道具编辑保留所有类型、丹药效果、法宝词缀与预览字段。抽屉有固定操作栏、就地成功/错误反馈、重复提交锁、未保存关闭提示和归档确认。
- 两个商店的目录与编辑分开；收起编辑保留草稿。道具选择使用独立抽屉。
- 赞助订单、订单详情、档位映射、历史手动发放分别展示；配置与原始快照默认折叠，订单筛选不覆盖未保存的映射输入。
- 邮件、游戏邮件、兑换码和模板按内容、范围、奖励、提交、结果分区；变量与原始结果默认折叠。
- 反馈、模板、兑换码列表在窄屏使用逐条卡片；反馈处理独立打开并保留未提交留言。
- 公告、社群、在线人数、秘境、蜃楼敌人、LLM 观测和对战模拟器统一按功能分区。蜃楼手动生成与对战样本筛选默认折叠。
- 后台显示断网提示，保留当前页输入。原有侧边栏、路由及权限边界继续使用。

## 范围与发布方式

只更新管理端 UI 及隔离验收脚本。未修改 API 契约、游戏规则、数据库结构或服务器运行配置。使用独立候选客户端构建；上线时原子交换静态客户端目录，并保留旧的带哈希资源供已打开的页面继续加载。

生产实例：`https://daoyou.yanji.sbs`。备份：`/data/backups/daoyou-admin-panels-20260911`。候选及验收记录：`/data/projects/daoyou/output/admin-panels-candidate`。

## 验证方式

- 修改文件的 Prettier、ESLint；初次完整 app/node TypeScript 检查，以及最后 app 检查；Vite client build。
- 独立 PostgreSQL 库仅复制 schema，不复制生产记录；独立 Redis、NATS；真实 Better Auth 管理员和普通账号均为虚构测试账号。
- 真实 API 验证未登录 401、普通用户 403、管理员读取、无效参数拒绝以及材料生成，共 7 项。
- 材料生成环境无 LLM 密钥，实际验证了项目现有的默认文案回退及数据入库，未测试收费模型文案。
- 浏览器覆盖 390×844、430×932、768×1024、1440×900 的 20 个页面，以及目录分页、详情、生成、编辑、归档、每日配置、失败反馈、断网恢复、草稿保留、菜单导航。
- 首轮发现平板列表溢出，已修正卡片断点和 grid 子项最小宽度；反馈输入验收选择器补充了标准 htmlFor 关联支持。原始失败报告保留。
- 页面和输入流程使用候选客户端加真实隔离后端；未使用生产管理员会话，未向真实玩家发邮件或奖励。

最终构建 ID、通过数量、线上健康结果记录于备份目录的 `release.json` 与 `live-verification.json`。回退所需的客户端、源文件和原始哈希位于备份目录；部署脚本发生异常会自动还原。验收结束后删除专用测试容器、网络和临时凭据。

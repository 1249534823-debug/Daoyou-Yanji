# 稳定性修复第一批

范围：源代码审查中的 F01–F07。保持现有品牌、界面风格、战斗规则及奖励流程。

- 秘境匹配使用专用工作线程；与在线战斗结算线程独立。最多四个等待任务，等待上限十秒、执行上限二十秒；异常重建线程。角色修改锁仍覆盖匹配、校验和持久化，匹配失败不扣入场消耗、不占每日次数。
- 有生成种子的随机属性词缀使用独立投影种子，保证守卫跨线程、重建时属性一致；无种子的普通造物仍按原规则随机，已有装备不重算。
- 生成者账号绑定临时角色；气运索引必须是三个不同的合法整数。重投次数由 Redis 原子控制，原始过期时间不延长。保存增加数据库事务锁与持久回执，重试不重复创建角色或发放新手邮件。
- 坊市新增数据库购买凭证，购买记录、扣款、入库同事务完成。重复购买和批量冲突全单回滚，缓存丢失不再放开限购。
- IP限流依据真实连接对端，只有精确配置的可信代理可提供覆盖后的 X-Real-IP；忽略 CF/XFF/Forwarded。Redis故障时写入及高成本接口关闭，明确列举的普通查询可降级。
- 任务错误不再阻塞洞府；显示错误、重试和缓存数据提示。
- 存活 `/api/live` 与就绪 `/api/ready` 分离；兼容 `/api/health-check` 增加数据库及秘境线程。数据库探测复用业务池、有界超时，连接耗尽后最多保留一个待获取连接。

验证使用独立 PostgreSQL、Redis、NATS 与虚构账号，不在运营数据库注入故障或测试记录。脚本包含气运规则、并发创角、越权、过期、重试、并发交易、回滚、缓存丢失、代理头、数据库/Redis故障、工作线程及入场验证；任务页面覆盖390×844、430×932、768×1024、1440×900。

发布需要停写、排空旧应用，应用0035迁移，并导入仍存在的当前批次Redis购买标记。已经丢失的历史标记无法还原。数据库迁移为增量表；回滚应用时保留购买凭证和玩家最新数据，不恢复旧数据库覆盖玩家进度。

本批不是完整容量压测，也不包含研究报告建议的新玩法。运行日志和验证结果保存于候选目录output及服务器发布备份目录。
